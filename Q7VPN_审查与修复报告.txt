Q7VPN V5.2 工程包 · 审查与修复报告
====================================
审查对象：Q7VPN_V5_2_水晶流光科技.zip（Q7vpn_V4_Starter）
交付时间：2026-10-28
结论：架构和视觉都在水准上，但有 11 处会直接踩坑的缺陷，其中 2 处上线必炸。已全部修复并实测通过。

────────────────────────────────────────
一、包里到底是什么
────────────────────────────────────────
两个独立工程：

1) web/     Flask 网站（账户注册登录、节点导入导出、安全中心、图片验证码、IP 失败锁定）
   依赖 Flask + Flask-WTF + Flask-Limiter + gunicorn，数据库 SQLite。

2) android/ 安卓原生 MVP（导入 TXT 节点、解析 VLESS/SS、TCP 可达性检测、分享给代理客户端）
   单 Activity，纯 Java，无第三方依赖。**不含 VPN 隧道内核**（原 README 已声明，属实）。

原包自述"可继续开发的工程包"，这个定位是对的。问题在于：它现在跑起来会在几个关键点上直接失败，
而且失败方式很隐蔽（不报错，只是登录不上、或者页面 500）。

────────────────────────────────────────
二、会直接导致失败的问题（按严重程度）
────────────────────────────────────────

【致命 1】SQLite 连接泄漏 + 嵌套写入 → 数据库锁死
  位置：app.py 的 db() 函数、recover() 视图
  原因：`with db() as con` 用的是 sqlite3 自己的上下文管理器，它只提交事务、**从不关闭连接**。
        15 处调用全部泄漏句柄。更糟的是 recover() 在 `with db()` 块内部又调用 log_event()，
        后者另开一个连接写同一个库 —— 前一个连接还握着写锁，第二个直接等死。
  实测：走一遍"忘记密码 → 重置密码"，页面直接 500：
        sqlite3.OperationalError: database is locked
  修法：db() 改成真正的上下文管理器（try/commit/except rollback/finally close），
        开 WAL 模式 + busy_timeout=15s，recover 里的日志写到事务之外。

【致命 2】配了持久化磁盘就起不来
  位置：DB_PATH 初始化
  原因：Q7VPN_DB_PATH 指向 /var/data/q7vpn.sqlite3 时，如果该目录还没建好（Render 磁盘挂载
        的典型时序），sqlite3.connect 在 import 阶段就抛异常，整个应用启动失败。
  修法：连库前自动创建父目录。

【致命 3】/health 会被自己的限流打死
  原因：全局限流 300 次/小时，/health 也在里面。Render / uptime 监控每 10-30 秒探一次，
        一小时 120-360 次 —— 探活一多就被 429，平台判定服务不健康，站点被摘掉。
  修法：/health 明确 @limiter.exempt。

【高危 4】重启即全员掉线
  原因：SECRET_KEY 没配时用 "CHANGE-ME-..." + 随机串，每次进程重启都变 → 所有人的会话失效。
  修法：没给 SECRET_KEY 时生成一次并落到 instance/secret_key（0600 权限）复用。

【高危 5】本地/内网用 http 访问会"登录不上"，且没有任何错误提示
  原因：SESSION_COOKIE_SECURE 默认 1，浏览器在 http 下不回传 Cookie，登录 POST 成功、
        跳转过去还是未登录状态，看起来就是"密码对了但没进去"。本地调试 100% 踩。
  修法：行为保留（线上 https 必须 1），但启动时打印明确警告，README/部署脚本写清什么时候设 0。

【中危 6】验证码输错也算"密码失败次数"，5 次锁整个 IP
  原因：验证码校验失败也调 record_auth_failure()。用户手抖看错两次验证码，第三次密码正确
        也进不去，还会被锁 5 分钟 —— 这是把真人挡在门外，挡不住脚本（脚本每次都能读验证码）。
  修法：验证码错误只换一张，不计入密码失败次数；爆破风险由该路由 20 次/分钟限流兜住。

【中危 7】页面停留久了提交表单，见到英文裸 400
  原因：CSRF token 失效时 Flask-WTF 直接返回英文 "The CSRF session token is missing"。
  修法：加了 CSRFError 处理器，中文提示 + 跳回对应页面。

【中危 8】找不到"密码重置"的安全事件
  原因：recover() 里 log_event 没传 user_id，用户当时未登录 → 事件挂在 NULL 上，
        安全中心永远显示不出"密码重置"这条。用户会怀疑是不是被人改过密码。
  修法：重置成功时带上该用户 id 记录事件。

【中危 9】429 没有页面，直接吐纯文本
  修法：补了一个与全站视觉一致的限流提示页（rate_limited.html），状态码保持 429。

【安卓 10】节点只在内存里，退出/被杀就全丢
  原因：nodes 是纯内存 ArrayList，没有落盘。导入 200 条、切个后台被系统回收，回来变 0 条。
  修法：SharedPreferences 持久化（含当前选中项），启动加载、导入/选择/退出时保存。
        实测：杀进程重进，节点和选中状态都还在。

【安卓 11】固定 4 线程做延迟检测，节点一多就是灾难
  原因：线程池写死 4 个，每个节点超时 2.5 秒。1000 个节点 → 排队 10 分钟以上，
        期间界面看着像卡死。
  修法：并发按节点数扩容（上限 16），并且重复点检测会重建线程池，不会越积越多。

【顺手修的】
  · 安卓工程没有任何启动图标，装到手机上是个默认白块 → 已按网站 V5.2 的水晶流光风格做了整套
    mipmap 图标（48/72/96/144/192 + roundIcon）。
  · 应用名 "Q7vpn" 统一成 "Q7VPN"。
  · /health 的版本号停留在 5.0，改成 5.2.1。
  · 节点导出、删除接口没限速 → 加上 60 次/分钟。
  · 安全响应头（nosniff / X-Frame-Options / Referrer-Policy / Permissions-Policy）。
  · 时间显示跟着服务器时区跑（Render 是 UTC，用户看到的是差 8 小时）→ 默认 +8，可用
    Q7VPN_TZ_OFFSET 改。
  · security_events / nodes 加了索引（安全中心按用户倒序查 30 条，数据一多会慢）。
  · 多 worker 并发建表会撞锁 → init_db 加了重试。
  · 补了 429 页面模板。

五、怎么把网站跑起来（三条路，任选一条）
────────────────────────────────────────
A. 有自己的 Linux VPS（最简单）
   cd web && sudo bash deploy_vps.sh
   装依赖、建 venv、注册 systemd、配 nginx 反代、跑健康检查，一条命令到底。
   跑完浏览器打开 http://你的IP/ 就能注册。

B. 有 Docker
   cd web && docker compose up -d
   数据落在 q7vpn-data 卷里，重建容器不丢。

C. Render（原工程就为它写的）
   Build: pip install -r requirements.txt
   Start: gunicorn app:app
   环境变量必设：SECRET_KEY、IP_HASH_SALT、Q7VPN_DB_PATH=/var/data/q7vpn.sqlite3
   注意：免费实例的文件系统是临时的，重启即丢库；要长期用请挂磁盘或用 Postgres。

本地自测（http 访问）务必：COOKIE_SECURE=0 python3 app.py
否则浏览器不回传 Cookie，你会以为登录功能坏了。

────────────────────────────────────────
六、没做的 / 需要你知道的
────────────────────────────────────────
1. **VPN 隧道没实现**，这版仍然只是"节点管理 + 交付给别的客户端"。
   原工程自己写清楚了：缺 sing-box/libbox 内核、VpnService 生命周期、TUN 描述符、VPN 授权弹窗。
   这是下一步最大的工作量（要接 libbox.aar + 写 VpnService + 处理路由和 DNS）。
2. 网站与安卓之间没有账户同步 API，网站导入的节点不会下发到 App。原工程也没做。
3. APK 用的是 debug 签名（自签）。自己装、自己用没问题；要上应用商店必须换成正式签名，
   keystore 自己保管好——丢了就再也发不了同包名的更新。
4. 真机验证我没做（本平台不能运行上传的工程，只做了编译和静态审查）。偏移、TCP 检测、
   分享到具体客户端的跳转，这些得你在手机上点一遍。
5. 网站公网部署这次没成：部署机端口池满了（8100-19999 全占），重试 4 次都失败。
   所以上面给了三条自部署路径，都是完整的、可执行的。
